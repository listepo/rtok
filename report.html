  • Duplicated responsibilities. Three tools compress Bash output (rtk, lean-ctx, token-optimizer), three compress reads, two keep memory (claude-mem, engram), three or four build code graphs (~85 MCP tools).
  • The lever is context × turns. A 17 K-token Read on turn 10 of 60 costs 1.25 × 17 K to cache and 0.1 × 17 K × 50 to keep. Shrinking early and clearing old results beats shaving a little everywhere.
  • Hooks cannot fix results after the fact. PostToolUse only adds context (verified in docs). Real shrinking needs PreToolUse rewriting, MCP tool replacement, or an API proxy. The binary needs all three surfaces.
  • Deliverables. ~/GitHub/rtok/plan.md (11 phases, 50 Haiku-sized tasks, each with a machine check) and research.md (matrix, measurements, fact-check ledger).

Architecture

Rust, one static binary, in-tree plugins behind one trait selected by Cargo features. No WASM, no subprocess plugins, no daemon in v1: hooks are per-invocation and must stay under 10 ms; MCP and proxy are long-running by nature.

  CC["Claude Code · Cursor · OpenCode"]
  CC -- "hooks (stdin JSON)" --> H["rtok hook <event>"]
  CC -- "MCP stdio" --> M["rtok mcp"]
  CC -- "ANTHROPIC_BASE_URL" --> P["rtok proxy :8790"]
  P --> API["api.anthropic.com"]
  H --> BUS["EventBus → plugins"]
  M --> BUS
  P --> BUS
  BUS --> DB[("rtok.db · SQLite + FTS5")]
  BUS --> AR[("archive/ raw payloads")]
  S["rtok stats · bench · doctor · setup"] --> DB

Plugin trait

trait Plugin {
  fn manifest(&self) -> Manifest;        // id, Native|Adapter, surfaces
  fn pre_tool(&self, ev, cx) -> Option<PreToolDecision>;
  fn post_tool(&self, ev, cx) -> Option<String>;   // context only
  fn session_start(&self, ev, cx) -> Option<Injection>;
  fn prompt_submit(&self, ev, cx) -> Option<Injection>;
  fn pre_compact(&self, ev, cx);
  fn mcp_tools(&self) -> Vec<ToolDef>;
  fn proxy_filter(&self, req: &mut MessagesRequest, cx)
      -> Vec<Measurement>;
}

Rules every plugin obeys

  • Measured or it does not exist. Measurement rows are the only way savings enter the DB.
  • Lossless by default. Originals live in archive/; expand <id> brings them back.
  • Budgeted injection. One plugin owns SessionStart/UserPromptSubmit output, 800 tokens, byte-stable.
  • Cache-safe proxy. Rewrite decisions are keyed by tool_use_id and persisted, so the frozen prefix never changes; system, tools and the last 4 turns are never touched.
  • Fail open. Any error returns the unmodified input and still exits 0.
  • Adapter before native. Wrap codebase-memory-mcp and rtk first; build in-tree only when measured.

09

Deliberately skipped in v0.1

  • LLM-based compression (LLMLingua, claude-mem-style extraction): spends tokens to save tokens; no positive independent number for code.
  • Embeddings and semantic search: no measured need; adds a model download and a daemon.
  • Own tree-sitter call graph: three graph tools are already installed; adapter first, native only if the adapter is measured to cost more.
  • Semantic response cache (bifrost): agent requests carry 100 K+ token contexts that never repeat at 0.9 similarity; a hit returns an answer to a different prompt.
  • WASM or subprocess plugins: 3× slower or 100 ms per spawn; nothing in the catalogue needs another language yet.
  • Codex Responses-API proxy: MCP only until Codex traffic is measured.
10

Risks and open questions

  • Cache busts from the proxy itself. A rewrite that differs between turns invalidates the prefix and costs more than it saves. Mitigation: decisions keyed by tool_use_id, never touch the last 4 turns, cache-health report (T5.5) before enabling compress.
  • Hook order with legacy tools. rtk's and rtok's PreToolUse rewrites both wrap Bash; run additive only until P9 replaces rtk's hook.
  • Tool search vs base URL. Docs say setting ANTHROPIC_BASE_URL disables MCP tool search by default, yet deferred tools are visible here. rtok doctor settles it; if search is off, ~250 tool descriptions may be in every prompt.
  • Estimator error ±15 %. Ratios between configs are safe; absolute token counts are not. The proxy's usage counters are the ground truth; calibrate with count_tokens when a key is present.
  • Fable/Mythos pricing. The cost split assumes output at 5× input; adjust in rtok stats --price.
  • Ponytail/terse effects are model-dependent and only self-benchmarked; keep them as data and A/B them (P7).
